## 1. Безопасность

**S1 · Критично — `GET /api/fatal` убивает процесс.**
`si-game-service/src/api/rest/router.ts:9-11` → `process.exit(1)` без авторизации. Любой, кто достучится
до порта, роняет сервер; всё состояние игр хранится только в памяти и теряется.
*Фикс:* удалить маршрут.

**S2 · Критично — path traversal при загрузке пака.**
`si-game-service/src/api/rest/upload/controller.ts:17`:
`fs.copyFile(file.filepath, path.join(siqDir, file.originalFilename))`. Имя файла из multipart полностью
контролирует клиент (`../../dist/...`) → запись произвольного файла с правами процесса.
*Фикс:* `path.basename()`, допускать только `.siq`, проверять, что итоговый путь внутри `siqDir`.

**S3 · Высокий — Zip Slip при распаковке ассетов.**
`si-game-service/src/entity/SiqPackage.ts:143-153` пишет в
`path.join(packDir, decodeURIComponent(file.entryName))`. Архив с записью вида `Images/..%2F..%2F…`
после декодирования выходит за пределы `packages/<gameId>`.
*Фикс:* `path.resolve` + проверка префикса `packDir`.

**S4 · Средний — чтение произвольного zip по socket-событию.**
`selectPack` → `Game.startGame(file)` → `parseSIQ(\`./siq/${file}\`)` (`si-game-service/src/entity/Game.ts:205`),
`file` не проверяется. *Фикс:* как в `removePack` — сверять со списком файлов `siqDir`.

**S5 · Средний — нет авторизации вообще.**
Любой клиент может управлять любой игрой, заливать файлы до 1 ГБ (`si-game-service/src/app.ts:34-39`),
удалять паки. CORS `origin: '*'` + `credentials: true` (`app.ts:25-30`). Для LAN-вечеринки это
осознанный компромисс, для публичного деплоя — нет.
*Варианты:* admin-токен, генерируемый при старте и зашиваемый в QR админки; upload/delete/exit — только с токеном.

**S6 · Низкий — `node --inspect` в прод-команде.** Корневой `Dockerfile` (CMD) и `si-game-service/package.json`
(`start`). Инспектор слушает 127.0.0.1 внутри контейнера, но в проде ему не место.

**S7 · Низкий — upload возвращает внутренний объект formidable** (`ctx.body = { file }`) с серверным путём temp-файла.

## 2. Баги и надёжность

**B1 · Высокий — падение процесса при распаковке пака.**
`void this.saveAssets(...)` и `siq.images.forEach(async …)` (`SiqPackage.ts:65,143-153`): ошибки записи
или `URIError` из `decodeURIComponent` (имя с одиночным `%`) становятся unhandled rejection → в Node ≥ 15
процесс завершается. Кроме того, игра стартует до окончания записи файлов — первые картинки могут отдавать 404.
*Фикс:* `await Promise.all(...)` с try/catch, стартовать игру после распаковки.

**B2 · Высокий — после переподключения сокета клиент «мертвеет» до перезагрузки страницы.**
Сервер создаёт новый `Controller` на каждое соединение (`app.ts:79-90`) с `_isConnect = false` и без выбранной
игры. Клиент шлёт `handshake` один раз (`si-game-admin-2/src/pages/_app.tsx:16-18`) и не повторяет
`handshake`/`selectGame` на `connect`. Серверные обработчики в этом случае молча делают `return` без ack →
`emitWithAck` на клиенте висит вечно (таймаута нет). Сценарии: перезапуск сервера, моргнул Wi-Fi,
телефон ведущего ушёл в сон.
*Фикс:* на клиенте `socket.on('connect', …)` → handshake + повторный `selectGame`; на сервере всегда
отвечать ack (с ошибкой); на клиенте `socket.timeout(ms).emitWithAck(...)`.

**B3 · Средний — `Client.preValidate` не бросает ошибку.**
`si-game-admin-2/src/client/Client.ts:299-301`: `new Error(...)` без `throw`; перед этим цикл ждёт до ~4 минут.

**B4 · Средний — `getGame` для несуществующего id не отвечает.**
`si-game-service/src/api/socket/Controller.ts:58-70` не вызывает ack, если игры нет → страница с устаревшим id
остаётся пустой навсегда. Связано с B9.

**B5 · Средний — экран Results не восстанавливается при перезагрузке.**
`Controller.getScreenPayload` (`Controller.ts:873-955`) не обрабатывает `Screen.Results` и возвращает `Initial`;
в `ResponseGetGame.screenData` (`common/types.ts:231-252`) нет варианта Results. Перезагрузка на результатах
показывает ведущему выбор пака, игрокам — QR.

**B6 · Средний — админка не подписана на `OnStartResults`.**
`si-game-admin-2/src/pages/admin.tsx:163-175` (и `admin/[id].tsx`): у игроков экран результатов, у ведущего —
таблица с пустыми ячейками.

**B7 · Средний — `selectGame` не отписывает сокет от предыдущей игры.**
`Controller.ts:350-355` отписывает/подписывает только новую игру → при переключении игр слушатели старой
утекают, её события (очки, игроки) приходят в сокет.

**B8 · Средний — повторный выбор пака в той же игре.**
Старый `SiqPackage` остаётся подписан на `OpenQuestion`/`CloseQuestion` общего emitter'а
(`SiqPackage.closeGame()` нигде не вызывается) и может реагировать на события нового пака, вплоть до
`StartResultsOnCloseAllQuestions`. Дополнительно `Question` с ценой < 0 вызывает `close()` прямо в конструкторе
(`si-game-service/src/entity/Question.ts:53-55`) → `Game.onCloseQuestion` срабатывает во время парсинга пака
(чистит очередь, эмитит `StartTable` со старым паком).

**B9 · Средний — QR в консоли протухает после «Выход».**
`si-game-service/src/startupBanner.ts:83` печатает `/player/<id Default-игры>`, а `exit` закрывает игру и
создаёт новую Default с другим id (`Controller.ts:522-523`) → QR ведёт на пустую страницу (B4).
*Фикс:* QR на `/` — `pages/index.tsx` сам редиректит на первую игру.

**B10 · Средний — числа в тексте пака портятся и могут уронить UI.**
`XMLParser` в `si-game-service/src/utils/parseSIQ.ts:15-19` с дефолтным `parseTagValue: true`:
`007` → `7`, `0x10` → `16` (проверено на fast-xml-parser 4.4.0). Если текст страницы целиком число,
`Question.fillPages` кладёт number в `page.text`, а `si-game-admin-2/src/components/question/Page.tsx:19` и
`components/admin/AdminPage.tsx:19` вызывают `page.text?.replace(...)` → `TypeError`, белый экран.
*Фикс:* `parseTagValue: false` + приведение к строке.

**B11 · Низкий — группа ответов из одного варианта ломает загрузку пака.**
`Question.parseAnswerGroup` (`Question.ts:195-207`) итерирует `param.param` без проверки на массив; при одном
элементе парсер отдаёт объект → `TypeError: not iterable`. Ошибку глотает `Controller.selectPack` — ведущий
видит «ничего не происходит».

**B12 · Низкий — `removePlayer` не чистит очередь и `currentSelector`** (`Game.ts:237-245`) → «призрак» в очереди,
позиции остальных сдвинуты.

**B13 · Низкий — `addPlayer` отдаёт `queue: 0` вместо `null`** (`Game.ts:228`) → новый игрок подсвечен как
первый в очереди до следующего полного обновления.

**B14 · Низкий — `MediaPlayer.reset`: инвертированное условие раннего выхода** (`si-game-service/src/entity/MediaPlayer.ts:38`):
медиа на паузе в позиции 0 не возобновляется.

**B15 · Низкий — `PageBuilder.refresh()` не сбрасывает `_replic`** (`si-game-service/src/entity/PageBuilder.ts:76-86`):
реплика протекает на все следующие страницы (в UI `replic` не рисуется, поэтому пока незаметно).

**B16 · Низкий — `GET /api/packs` читает каждый .siq целиком и синхронно** (`api/rest/packs/controller.ts:9-12`)
на каждый запрос: блокирует event loop на больших паках; один битый файл в `siq/` даёт 500 на весь список.
*Фикс:* кэш имён по mtime + try/catch на файл.

**B17 · Низкий — temp-файлы загрузок не удаляются**: `copyFile` вместо `rename`, formidable их не чистит
(`upload/controller.ts:17`) → каждая загрузка оставляет копию (до 1 ГБ) в tmp.

**B18 · Низкий — удаление пака с `#`, `&`, `+` в имени не работает**: имя не кодируется
(`si-game-admin-2/src/store/packs.ts:25`). *Фикс:* `encodeURIComponent`.

**B19 · Низкий — нельзя выставить 0** из-за `if (value)` в `components/menu/ChangePointsModal.tsx:32-57`
(очки и громкость). Настройки громкости сервер хранит, но плеер их нигде не применяет.

**B20 · Низкий — `Results`**: `players.sort(...)` мутирует props (`components/Results.tsx:11`);
`distributeRows` показывает максимум 15 игроков, остальные молча пропадают.

**B21 · Низкий — `page.text?.replace('ё', 'e')`** (`Page.tsx:19`, `AdminPage.tsx:19`) заменяет только первое
вхождение и на латинскую `e`. Если цель — шрифт без «ё», нужен `replaceAll('ё', 'е')` или шрифт с глифом.

**B22 · Низкий — stale closure в админке.** `onStartTable` в `admin.tsx:104-110` зависит только от `[game]`, но
использует `players`. Сейчас это маскируется тем, что `onUpdatePlayer` (`admin.tsx:134-161`) мутирует объекты
игроков на месте; игроки, добавленные после последнего `fetchGames`, исчезают из таблицы при возврате к табло.
*Фикс:* функциональный `setPlayers(prev => …)` / общий store (см. A9).

## 4. Архитектура и поддерживаемость

**A1 · Средний — дубли `src/data.ts`.** Файлы `si-game-service/src/data.ts` и `si-game-admin-2/src/data.ts`
отличаются одной строкой (`packagesDir`). Алиас `@common/data` в обоих `tsconfig.json` указывает на *локальную*
копию, а `common/types.ts` импортирует enum'ы через него. Правка enum'а нужна в двух местах; рассинхрон
молча ломает протокол. Заодно админка тянет node-модуль `path` в браузер ради неиспользуемого `siqDir`.
*Фикс:* перенести enum'ы в `common/data.ts`, пути к каталогам оставить в сервисе.

**A2 · Средний — дубли страниц.** `pages/admin.tsx` ≈ `pages/admin/[id].tsx`, `pages/player.tsx` ≈
`pages/player/[id].tsx` (отличие — откуда берётся id). В проде (static export + SPA-fallback в Koa)
работают только `admin.tsx`/`player.tsx`; `[id]` используются лишь в `next dev`.
*Фикс:* тело страницы вынести в компонент, `[id].tsx` сделать тонкой обёрткой.

**A3 · Средний — `Controller.ts` на 1024 строки**: 31 обработчик с одинаковым шаблоном (guard'ы
`_isConnect`/`_selectedGame` + try/catch + ack). Обёртка `handler(fn, { needsGame })` сократит файл в разы и
даст единое место для валидации и ack-ошибок (B2, B4).

**A4 · Средний — нет валидации входящих payload'ов.** zod есть в зависимостях, но `schema.ts` нигде не
используется. Например, `setScoreValue` со строкой превратит очки в строку и сломает арифметику.
*Фикс:* zod-схемы Request* в `common/`.

**A5 · Низкий — инвертированная семантика `Question.isClose`**: `true` = вопрос ещё не сыгран, `close()`
ставит `false`. Переименовать (`isAvailable` / `isPlayed`).

**A6 · Низкий — зависимость от порядка подписчиков.** `Game` подписан на общий emitter раньше `SiqPackage`,
поэтому `Game.onOpenQuestion` эмитит `StartQuestion` через `process.nextTick`, чтобы пакет успел выставить
`currentQuestion`. Хрупко; лучше явный вызов вместо двух подписчиков на одно событие.

**A7 · Средний — тестов фактически нет.** Пустые `describe`, закомментированный код; `siq.test.ts` требует
`packages/` и `siq/test.siq` (оба в `.gitignore`) и проверяет устаревший порядок экранов.
*Предложение:* маленький тестовый `.siq` в `test/fixtures/`, тесты на state machine `Game.next()`,
построение страниц `Question`, типы вопросов, финальный раунд.

**A8 · Низкий — lint сервиса красный** (33 ошибки, 29 — `--fix`); `.eslintignore` исключает `test/`.

**A9 · Низкий — состояние фронтенда.** По 10 `useState` на страницу, мутации объектов на месте, stale
closures (B22). Store игры на zustand (уже в зависимостях) с reducer'ом по серверным событиям уберёт
класс ошибок и дубли `onUpdatePlayer` в четырёх компонентах.
