# Окно запуска SI Game — план

Дата: 2026-09-19. Статус: план, реализации нет. Превью дизайна: [`docs/launcher-preview.html`](launcher-preview.html)
(открыть в браузере; переключатели macOS/Windows и состояния сервера).

## Зачем

Сейчас после двойного клика открывается консоль с QR из символов. Нужно нативное окно, из которого хост за пару
кликов запускает игру: видит адрес для телевизора, открывает пульт ведущего и экран игроков, понимает, что делать
с полным экраном и файрволом. Консоли быть не должно.

## Что в окне

| Блок | Содержимое | Поведение |
|---|---|---|
| Шапка | Логотип, «SI Game», статус: «Игра запущена · порт N» / «Запускается…» / ошибка | Статус по сигналу готовности сервера |
| Карточка QR, вкладка «Телевизор» | Адрес в локальной сети `http://192.168.x.x:PORT`, QR, «Скопировать», выбор сети (Wi‑Fi / Ethernet / …) | Выбор сети запоминается |
| Карточка QR, вкладка «Телефон ведущего» | QR сразу на `/admin/<id>` (с `?token=`, если включён admin-токен) | Для ведущего с телефоном |
| Подсказка полного экрана | Windows: «F11 (на ноутбуке — Fn+F11)»; macOS: «⌃⌘F, в Chrome/Edge панель скрывается ⇧⌘F» | Текст по ОС хоста |
| Кнопка «Открыть пульт ведущего» | Открывает `/admin/<id>` в браузере по умолчанию | Через opener, не через webview окна |
| Кнопка «Открыть экран игроков здесь» | Открывает `/player/<id>` в браузере по умолчанию | Для ТВ, подключённого к этому компьютеру |
| Факты | «Подключено: ТВ 1 · пульт 1», «Паки: N · открыть папку», «Admin-токен: вкл/выкл» | Счётчик — реальные socket.io-подключения |
| Подвал | Подсказка про файрвол для ОС, версия, «Остановить и выйти» | Закрытие окна тоже останавливает игру |

Дополнительно на экране игроков (веб): кнопка «На весь экран» (Fullscreen API, `navigationUI: 'hide'`) —
работает мышью, клавиатурой и кнопкой OK пульта ТВ; подсказка про F11 остаётся запасным вариантом.

## Технология

Исследование 2026-09-19 (версии и тесты на этом Mac — в истории сессии):

| Вариант | Размер загрузки (mac / win) | Трудоёмкость | Вид | CI | Главные риски |
|---|---|---|---|---|---|
| **Tauri 2.11 + наш pkg-сервер как sidecar** | ≈30–33 МБ DMG на архитектуру / ≈30 МБ NSIS | Средняя, окно на HTML/CSS + немного Rust | Нативное окно, системный webview | tauri-action: 2 macOS-таргета + windows-latest | Rust в тулчейне; hardened runtime ломает pkg-бинарник без entitlement `allow-jit` |
| Neutralino 6.9 + sidecar | ≈30 МБ / ≈25–39 МБ | Низкая–средняя | Системный webview | Один macOS-раннер | Нет настоящего .app, дочерние процессы не гарантированно убиваются при выходе, нет инсталлятора |
| Electron 44 (сервер в utilityProcess) | ≈130–160 МБ | Низкая, всё на JS | Chromium | Средняя | Размер в 4–5 раз больше |
| SwiftUI + WinForms/.NET + sidecar | ≈30 МБ / 5 КБ–52 МБ + сервер | Высокая, два языка | Полностью нативный | Два тулчейна | Двойная поддержка |

**Рекомендация — Tauri 2** (закрепить `~2.11`, Tauri 3 пока alpha). Окно маленькое (≈3 МБ), настоящие `.app`/DMG
и NSIS-инсталлятор, single-instance и открытие ссылок — готовыми плагинами, сервер остаётся тем же бинарником.

## Архитектура

```
SI Game.app / SIGame-setup.exe
└─ launcher (Tauri, Rust + HTML)          ← окно, кнопки, трей не нужен
   └─ sidecar: sigame-server (@yao-pkg/pkg, Node 24)  ← текущий сервер без изменений в логике игры
        stdout: строка SIGAME_READY {json}  → статус окна
        stdin: закрыт = лаунчер умер → сервер завершается
```

- **Запуск сервера из Rust**: `app.shell().sidecar("sigame-server")` с env `PORT`, `SIQ_DIR`, `PACKAGES_DIR`,
  `SIGAME_LAUNCHER=1`. `CommandChild` хранится в состоянии приложения, stdout читается постоянно
  (канал событий на 1 элемент — если не читать, сервер заблокируется на записи).
- **Готовность**: сервер в режиме лаунчера печатает одну машиночитаемую строку
  `SIGAME_READY {"port":4000,"addresses":[{"ip":"192.168.1.135","iface":"en0","score":…}],"gameId":"…","tokenRequired":false}`
  вместо баннера с QR.
- **Остановка**: при `RunEvent::ExitRequested` лаунчер убивает сервер; страховка на случай падения лаунчера —
  сервер при `SIGAME_LAUNCHER=1` завершается по концу stdin (проверено на macOS с Node 24), на Windows дополнительно Job Object.
- **Один экземпляр**: `tauri-plugin-single-instance` — повторный запуск разворачивает уже открытое окно.
- **Данные**: лаунчер передаёт `SIQ_DIR`/`PACKAGES_DIR` явно — `~/Library/Application Support/SIGame`,
  `%LOCALAPPDATA%\SIGame`; productName инсталлятора ≠ имени папки данных, иначе на Windows паки окажутся в папке установки.
- **Логи**: `tauri-plugin-log` → `~/Library/Logs/SIGame`, `%LOCALAPPDATA%\SIGame\logs`; кнопка «Открыть папку с логами».
- **Окно**: статический HTML/CSS/TS без фреймворка (`withGlobalTauri`), начальный статус командой `get_status`,
  дальше событие `server-status`. Все действия (открыть ссылку, копировать, стоп) выполняются в Rust —
  webview почти без прав.

## Изменения в сервере

1. Режим лаунчера (`SIGAME_LAUNCHER=1`): строка `SIGAME_READY`, без QR-баннера, выход по концу stdin.
2. Порты: явный `listen` на `0.0.0.0` и проверка — сейчас, если порт 4000 держит другая программа на `127.0.0.1`,
   Node стартует без ошибки и ТВ попадает в чужое приложение (проверено на этом Mac). Если 4000 занят — `/api/health`
   (это уже SI Game?) → запасные 4001–4010 → любой свободный; окно показывает реальный порт.
3. Выбор адреса LAN: штрафы для `bridge*`, `utun*`, `vmnet*`, `vboxnet*`, `docker*`, `/32`-масок и адресов на `.1`;
   список всех кандидатов для выпадающего меню (сейчас мост ВМ `bridge100` получает тот же вес, что и Wi‑Fi `en0`).
4. `/api/health` и счётчик подключений по ролям (ТВ / пульт) для окна.
5. Windows: метаданные exe (`resedit`: «SI Game», иконка) — иначе запрос файрвола показывает «Node.js JavaScript Runtime».

## Сборка и CI

- Сайдкар на каждый таргет: `binaries/sigame-server-aarch64-apple-darwin`, `-x86_64-apple-darwin`,
  `-x86_64-pc-windows-msvc.exe` — собираются существующим `scripts/package.js` до `tauri build`.
- macOS: два DMG (arm64 и x64) — универсальный бинарник из двух pkg-сборок через `lipo` не запускается (проверено).
  `signingIdentity: "-"`, entitlements с `com.apple.security.cs.allow-jit` (без него ad-hoc + hardened runtime роняет
  Node 24), `minimumSystemVersion: "13.5"` (требование Node 24).
- Windows: NSIS, установка для текущего пользователя без прав администратора, WebView2 — стандартный загрузчик Tauri
  (скачивается только если его нет; на Windows 11 он встроен).
- GitHub Actions: `tauri-apps/tauri-action@v1`, матрица `macos-latest` × 2 таргета + `windows-latest`;
  артефакты на push, релиз по тегу — как сейчас в `build.yml`/`release.yml`.
- Локально нужен Rust (`rustup`), сейчас на этом Mac его нет.

## Первый запуск у пользователя

- macOS 15+ (Sequoia/Tahoe): без Developer ID — «Не удалось проверить…» → Системные настройки → Конфиденциальность
  и безопасность → «Всё равно открыть» (кнопка доступна ~1 час после попытки). Правый клик → «Открыть» больше не работает.
  Запрос файрвола повторяется после каждого обновления (ad-hoc подпись меняется).
- Windows: SmartScreen «Подробнее → Выполнить в любом случае»; при включённом Smart App Control Windows 11 неподписанное
  приложение не запустится вообще — лечится только сертификатом. Новые сети Windows 11 помечает «Общедоступными» —
  окно предупреждает и ведёт в настройки сети.
- Окно показывает счётчик подключений: это единственное реальное подтверждение, что ТВ достучался до сервера.
