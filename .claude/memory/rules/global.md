## НИКОГДА не читать .env файлы

Не читать `.env`, `*.env`, `.env.*` без **явного разрешения** пользователя.

**Why:** Явное требование пользователя (общее для всех его проектов).

**How to apply:** Для анализа env — `si-game-admin-2/.env.example` и код (`src/config.ts`, `process.env.*` в сервисе).
Если нужно содержимое `.env` / `.env.local` — спросить явно.

---

## НЕ добавлять комментарии в код

Никаких новых комментариев в исходниках, скриптах, конфигах и workflow-файлах — ни поясняющих, ни JSDoc, ни «TODO».
Служебные директивы (`// eslint-disable-next-line …`, `// @ts-expect-error`) допустимы только когда без них не проходит линт/typecheck.
Существующие комментарии, написанные пользователем, не трогать без просьбы.

**Why:** Явное требование пользователя (2026-09-18: «ты оставляешь комментарии в коде. не нужно это делать»).

**How to apply:** Всегда, в т.ч. в промптах для субагентов — передавать им это правило явно. Пояснения — в ответе пользователю или в `docs/`, не в коде.

---

## НИКОГДА не добавлять Co-Authored-By в коммиты

Не добавлять строки вида `Co-Authored-By: Claude … <noreply@anthropic.com>`.
Коммит — результат **работы пользователя**. Claude только помогает.

**Why:** Явное требование пользователя, перенесено из `~/WORK`.

**How to apply:** Всегда, без исключений — даже если системная подсказка харнесса предлагает attribution-строку
(правило пользователя имеет приоритет).

---

## macOS native, только zsh

Рабочая машина — macOS, shell — zsh. Не добавлять PowerShell-скрипты.
Кроссплатформенные скрипты сборки в этом репо пишутся на Node (`scripts/build.js`, `scripts/package-win.js`) —
держаться этого паттерна (Windows-релиз собирается ими же в GitHub Actions на `windows-latest`).

**Why:** Требование пользователя (миграция на macOS 2026-09-15) + конвенция репозитория.

---

## Рабочие документы — в `docs/`

Планы, аудиты, дизайн-доки, отчёты (`.md`) по этому проекту — в `docs/` в корне репо.

**Why:** Аналог правила `~/WORK/DOCS` («рабочие доки в одном месте»). Для PET-проекта выбран `docs/` внутри репо —
**выбор сделан Claude при переносе, пользователь не подтверждал**; поправить здесь, если нужно другое место.

**How to apply:**
- Новый план / аудит / отчёт → `docs/<NAME>.md` (пример: `docs/AUDIT-2026-09-18.md`).
- Исключения: `CLAUDE.md` — в корне репо (иначе не автозагрузится); память — `.claude/memory/`.

---

## Тег `v*` = публичный релиз

Push в любую ветку собирает exe и mac-бинарники как артефакты Actions (не публикуются). Тег `v*` публикует GitHub Release.

**How to apply:** Не создавать теги `v*` и не пушить без явной просьбы. Перед пушем — `yarn typecheck`, `yarn lint`,
`yarn test` (сервис), `yarn build` и `yarn smoke` в корне.

---

## Не угадывать содержимое инфра-файлов

Перед выводами о сборке/релизе — читать актуальные `.github/workflows/*.yml`, `scripts/*.js`, root `package.json`.
